# Test Plan – Sell Here E-commerce

## 1. Introduction

This test plan defines the manual testing strategy for the **Sell Here** e-commerce web application. It outlines the testing objectives, scope, approach, environment, deliverables, and completion criteria used to verify that the application functions correctly and provides a reliable user experience.

---

# 2. Objectives

The objectives of this testing effort are to:

- Verify that application features function according to their requirements.
- Identify functional, usability, and UI defects.
- Validate application behavior across supported browsers.
- Ensure existing functionality remains stable after changes through regression testing.
- Document defects with clear reproduction steps and supporting evidence.

---

# 3. Scope

## In Scope

The following features are included in manual testing:

- User Authentication
- Anonymous Guest Sessions
- Product Browsing
- Product Search
- Shopping Cart
- Checkout
- User Profile
- Responsive User Interface
- Navigation
- Route Protection

## Out of Scope

The following items are not included in this phase:

- Performance Testing
- Load Testing
- Security/Penetration Testing
- Automated Testing
- API Testing

---

# 4. Test Types

The following manual testing activities will be performed:

- Functional Testing
- Smoke Testing
- Regression Testing
- UI Testing
- Responsive Testing
- Exploratory Testing

---

# 5. Test Environment

| Item             | Value                                          |
| ---------------- | ---------------------------------------------- |
| Application      | Sell Here                                      |
| Operating System | Windows 10                                     |
| Browsers         | Google Chrome, Mozilla Firefox, Microsoft Edge |
| Device           | Desktop                                        |
| Testing Method   | Manual Testing                                 |

---

# 6. Test Deliverables

The following QA documents will be produced:

- Test Plan
- Test Cases
- Bug Reports
- Regression Test Results
- Screenshots
- Video Evidence

---

# 7. Entry Criteria

Testing may begin when:

- The application is available for testing.
- The required feature has been implemented.
- The test environment is operational.

---

# 8. Exit Criteria

Testing is considered complete when:

- All planned test cases have been executed.
- Critical and High severity defects have been resolved or accepted.
- Regression testing has been completed successfully.
- Test evidence has been documented.

---

# 9. Defect Severity

| Severity | Description                                                        |
| -------- | ------------------------------------------------------------------ |
| Critical | Prevents core functionality from working.                          |
| High     | Major functionality is affected.                                   |
| Medium   | Functionality works but produces incorrect or misleading behavior. |
| Low      | Minor UI or cosmetic issues with minimal business impact.          |

---

# 10. Risks

Potential risks include:

- Browser compatibility differences.
- Network-related issues affecting data loading.
- Changes introduced during development causing regressions.
- Delays in defect resolution.

---

# 11. Conclusion

This test plan provides the framework for conducting structured manual testing of the Sell Here application. The associated test cases, bug reports, and regression test results serve as evidence of the testing activities performed throughout the project.
